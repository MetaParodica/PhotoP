# 실험적 AI 심도 기능 기획

2026-11-20 KST. 기준 main `a81cc7a22a9f2d3cea9b34d2c134cf17e4ba8f3c`.

사용자 결정: **외부 AI 기능은 설정에서 활성화하는 실험적 기능으로 제공하고, 사진에서만 가능한 기능은 사진 전용으로 구현한다.** [45 도입 조사](45-EXTERNAL-AI-TRACKER-ADOPTION-RESEARCH.ko.md)의 기술 후보를 이 제품 범위에 맞춰 적용한다. 이 문서는 구현할 동작·범위·검증 조건을 정한 기획이며 설정 UI나 모델 통합을 완료한 기록이 아니다.

## 1. 제공 원칙

- 각 실험적 기능의 기본값은 **꺼짐**이다. 사용자가 `심도 설정 → 고급 → 실험실`에서 기능별로 켠다. AI 구도 추천/코치/자동 리뷰 중지 정책은 유지한다.
- 사진·저장 영상·라이브의 활성화 상태와 지원 조건을 분리한다. 사진 기능을 켜도 영상 처리·뷰파인더 추론·자동 AF 동작은 함께 바뀌지 않는다.
- 사진용 모델/해상도/처리 시간으로만 가능한 개선은 **사진 전용**으로 완성한다. 영상·실시간 지원을 사진 기능의 선행 조건으로 두지 않는다.
- 실험적 공개는 선택 가능한 추가 처리다. 원본과 기존 심도 처리를 보존하고, 적용 성공/기존 방식 사용/실패를 결과에서 구분한다.
- 아직 추론할 수 없는 모델의 encoder-only 변환이나 지원하지 않는 실행 경로를 켜지는 기능으로 표시하지 않는다. 실제로 동작하는 항목부터 순차 공개한다.

MatAnyone 2의 사진 사용은 첫 프레임의 seed를 실제 alpha로 개선하는 경로가 확인될 때 제공한다. 영상 전용 모델을 같은 사진의 반복 처리만으로 고품질 사진 모델이라고 분류하지 않는다. 적합하지 않으면 별도 사진 매팅 모델을 비교하고, 해당 모델은 영상용 후보로 유지한다. 선택 인물이 없는 사진에서 인물 모델로 임의 물체를 처리하지 않는다.

사진 1차는 촬영 후 처리와 저장 사진 편집을 우선한다. 정지 이미지 편집 화면에서 보여 주는 처리 미리보기는 라이브 카메라 지원과 구분한다.

## 3. 설정과 사용 흐름

### 설정 진입

현재 `CameraQuickControls`의 심도 고급 설정에 `실험실` 진입을 추가하는 안을 기본으로 한다. 독립 설정 화면을 추가할 때도 같은 저장소·설정 값을 사용한다. 현재의 촬영 의도/코치 설정을 재활성화하는 경로로 연결하지 않는다.

1차 설정 항목은 `정밀 피사체 선택 · 사진 전용`, `인물 경계 개선 · 사진 전용` 두 개의 독립 스위치다. 실제 추론 경로가 구현된 항목을 활성화 대상으로 노출한다. 켜기로 모델 준비를 시작할 수 있지만 준비 완료 전에는 실제 처리가 활성화됐다고 표시하지 않는다. 기능별 한 줄 설명과 준비 상태를 함께 표시한다. 일반 사용자 설정에는 모델명·Core ML/ANE·tensor/정밀도 선택을 나열하지 않는다.

후속 영상 항목은 `기억 기반 피사체 추적 · 저장 영상`, 라이브 항목은 `실시간 피사체 추적`으로 별도 추가한다. 실제 지원 전에는 켜지는 placeholder를 만들지 않는다. 설정을 찾기 위해 촬영 모드를 바꿀 필요가 없게 하고, 모드 변경 시 설정 창을 자동으로 열지 않는다. 기존 박스형 뷰파인더와 하단 스크롤 패널을 유지한다.

### 사진 촬영/편집

1. 사용자가 사진 기능을 켠다. 처음 준비가 필요한 경우 실제 manifest의 모델 용량과 `준비 중` 상태를 보여 주며 준비 완료 전에는 적용됐다고 표시하지 않는다. 다운로드형이면 켜기 전 항목 설명에 다운로드가 필요함을 알리고, 해당 조작으로 준비를 시작한다. 추가 확인창을 반복하지 않는다.
2. 이후 촬영한 사진은 저장한 원본을 바탕으로 해당 기능을 처리한다. 셔터 입력·원본 보관을 긴 모델 추론 뒤로 미루지 않는다. 결과 준비 상태는 촬영 결과/보관함에서 확인한다.
3. 기존 사진에서는 사용자가 `사진 심도 개선`을 실행했을 때 재분석한다. 단순히 편집기를 열거나 설정을 켰다는 이유로 저장 사진 전체를 재처리하지 않는다. 적용할 대상을 탭하고 기존 f값·프로필·교정 UI로 결과를 조절한다.
4. 처리/원본 비교는 같은 사진·선택·설정으로 제공한다. 완료 시 별도 결과를 저장하고 AI 처리 메타데이터·앱 내 표시를 남긴다.

품질 한계 안내는 실험실과 해당 결과의 간단한 설명으로 제공한다. 촬영 화면에 반복 로그·모델 내부 상태·상시 경고를 추가하지 않는다.

## 4. 활성화와 실패 동작

설정의 **사용자 선택**, **실행 가능 상태**, **이번 결과에 실제 적용한 처리**를 각각 기록한다.

| 상태/이벤트 | 동작 |
|---|---|
| 기본 꺼짐 | 외부 실험 모델을 로드/다운로드/추론하지 않음. 기존 사진·영상 심도 경로 사용 |
| 켜기·준비 중 | 모델 hash/버전·파일/메모리 조건·실제 입력/출력 계약 확인 후 준비. 상태를 `준비 중`으로 표시 |
| 사진 모델만 사용 가능 | 해당 사진 기능만 사용. 영상 모드에서는 사진 전용임을 표시하고 영상/라이브 처리는 추가로 시작하지 않음 |
| 대상/인물 미검출·유효하지 않은 mask/alpha | 기존 심도 처리로 돌아가고 결과에 `기존 방식으로 처리` 표시. 다른 인물을 임의로 선택하지 않음 |
| 모델 로드 실패·메모리 부족·유효하지 않은 출력 | 해당 작업 중단·임시 파일 정리·원본 보존. 사용자 선택을 임의로 끄지 않고 실행 불가 이유와 재시도 경로 제공 |
| 작업 중 설정 끄기·선택 변경 | generation 갱신·협력 취소, 오래된 결과 폐기. 완성 전 파생물을 게시하지 않음 |
| 이미 저장된 실험 결과에서 기능 끄기 | 저장 결과·recipe·원본을 보존. 저장된 depth/matte로 비교/편집할 수 있고, 새 외부 AI 재분석만 중지 |
| 지원되지 않는 기기/OS/모드 | 가능한 사진 기능을 유지하고 해당 경로의 실행 불가 사유만 표시. 기기 이름만으로 모든 기능을 한꺼번에 차단하지 않음 |

사용 가능 상태가 준비됐다는 것과 모든 사진에서 모델이 성공했다는 것을 구분한다. fallback 결과에는 실제 사용한 기존 엔진을 기록하고 외부 모델이 적용됐다는 배지/메타데이터를 붙이지 않는다.

## 5. 모델·처리·보존 계약

- iOS18 Core ML 경로를 기본으로 한다. Core AI/iOS27의 특정 기능만 사용 가능한 경우 그 옵션에만 availability를 적용한다. SDK27 미검증을 사진 기능 전체의 출시 대기 사유로 만들지 않는다.
- 사진은 image encoder+prompt/mask decoder가 온전히 동작하면 제공할 수 있다. 영상 memory/perceiver/propagator의 완성을 요구하지 않는다. encoder만 변환된 상태는 사진 분할 기능의 완료 조건도 아니다.
- 사진의 분석 해상도는 모델 지원과 경계 검증을 기준으로 정한다. 288×512 인물 matte를 확대해 저장했다는 이유로64MP 모발 품질을 보증하지 않는다. 색/alpha를 가능한 Float/선형 처리로 유지하고 기존 high-resolution halo 타일 합성에 연결한다.
- 스틸·영상 모델의 runtime state/cache/입력 좌표를 공유해 섞지 않는다. 프리뷰와 최종 저장은 같은 원본·mask/depth·설정 스냅샷을 사용한다. 오래된 비동기 preview가 최신 선택을 덮지 못하게 한다.
- 원본 bytes/hash, SDR 출력, 위치 제거 공유본/위치 보존 원본 내보내기, AI 메타데이터·앱 공지 정책을 유지한다. 재편집 시 매번 모델을 다시 실행하지 않도록 사용한 mask/alpha/깊이·교정을 저장한다.
- recipe에 기능 ID·실험 버전·모델/가중치 hash·사용 모드·분석 크기·선택·실제 적용/fallback을 추가한다. 기존 v2/v3/v4 읽기를 유지하고 필요 시 새 recipe version을 명시한다. 새 결과는 UUID 기반 별도 번들로 atomic 게시한다.
- 선택한 모델의 고정 SHA·원문 조건·변경/복사 범위·가중치 hash·LICENSE/NOTICE를 일지와 고지에 기록한다. 사용자 허용 범위의 외부 구현을 검토하며 코드 조건과 가중치 조건을 구별한다.

## 6. 구현 진입점과 순서

아래 이름 중 신규 타입은 설계안이며 현재 존재하는 구현으로 표시하지 않는다.

| 단계 | 변경할 범위 | 완료 결과 |
|---|---|---|
| E0 설정/지원 정책 | 신규 `ExperimentalDepthPreferences`·기능/모드별 capability 판정, `CameraModel`·`CameraQuickControls` 연결 | 버전 있는 영구 저장, 모든 항목 기본Off, 사진/저장영상/라이브 독립 판정 |

| E2 사진 인물/고해상도 | 단일 사진 matte 검증·Float alpha·모델 분석/고해상도 합성, `DepthPhotoEditor`·보관함 편집 | 사진 전용 기능·원본 비교·교정·취소·재편집·새 recipe |

`DepthPhotoEditor`의 기존 “열기만으로 Vision/Core ML 재추론 안 함” 계약은 유지한다. 새 재분석은 명시적 동작과 별도 작업 세션으로 추가한다. 사진 전용 개선이 완성됐을 때 영상용 모델의 미완료를 이유로 해당 기능을 숨기지 않는다.

## 7. 실험 공개와 정식 품질 인수

**실험적 공개에 필요한 조건**은 실제 모델이 해당 모드에서 로드·추론되고, 선택/입출력·유한값/크기·오류 처리·원본 보존·취소·세대 분리·저장/복원·사용자 표시가 검증되는 것이다. 해당 변경의 iOS 빌드·네이티브 통합/UI 검사도 통과해야 한다. 명확한 잘못된 대상 적용·기본On·원본 훼손·취소 결과 게시 등 기능 오류는 고친 후 제공한다.

**정식 승격에 필요한 조건**은 기존 실제100장/10종 영상·기기 지속 성능·비교 평가다. 실험적 선택 제공과 정식 품질 인수를 별도로 기록한다. 위 전체 실사 평가의 미완료만으로 사용자가 켜서 시험하는 사진 실험 기능을 무기한 보류하지 않는다. 실험적이라는 이유로 미완성 placeholder를 동작하는 기능으로 노출하지도 않는다.

필수 회귀 항목:

- 신규/업데이트 설치 기본Off, 선택값 재실행 후 복원, 사진On 상태의 영상/라이브 외부 추론0회.
- 준비 실패/지원 불가/취소/대상 없음의 상태와 표시 일치. Off 상태에서 새 모델 로드/다운로드/추론0회.
- 사진1장·인물/비인물·근/중/원거리·가로/회전·서로 다른 원본 크기의 선택 좌표와 원본 비교.
- f값/프로필/선택을 빠르게 바꿀 때 stale 결과 폐기, 설정Off 중 작업 취소, 저장 중 변경 잠금과 임시 파일 정리.
- 실제 적용/fallback provenance, 원본 hash, 새 결과의 재열기·교정·추가 모델 없이 복원, 기존 recipe 호환.
- 영상/라이브는 각 옵션을 도입할 때만 해당 시간/메모리·AF/AE 잠금·원본/음성 동기 검사를 추가.

## 8. 이번 작업 상태

이번에는 사용자 결정에 맞춰 범위·설정 UX·사진 우선 독립 제공·실험 공개 조건을 기획했다. 외부 모델 가중치·설정 코드·recipe schema·카메라 동작은 변경하지 않았다. 새 모델 통합/정밀도 검증·실기기 품질/성능은 각 구현 단계에서 수행한다. 구현 시의 최우선 제품 범위는 이 문서이며45의이전 “저장 영상부터” 순서는 이 결정에 맞춰 조정한다.
