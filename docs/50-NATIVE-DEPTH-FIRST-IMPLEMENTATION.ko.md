# 네이티브 심도 우선 1차 구현 — 자동 AI 분리와 미리보기 예산

2026-11-25 KST. [49 계획](49-NATIVE-DEPTH-LENS-PRIORITY.ko.md)의 후속 개발. 기준 main `7f0f6c0`, 로컬 작업 중이며 새 앱 SHA/기기 인수는 아직 없다. 기존 조사·개발 일지의 미커밋 변경을 보존했다.

## 1. 반영한 동작

### 네이티브 사진과 실시간 AI 분리

- 센서 사진 심도를 활성화한 `.automatic` 모드에서 AI live preview를 자동으로 켜지 않는다. 사용자는 고급 설정의 기존 AI 프리뷰 스위치로 직접 켤 수 있다.
- 명시적인 `.ai` 입력, 또는 사진 심도를 지원하지 않는 `.automatic` 경로의 기존 AI 기능은 유지한다. `.measured`는 계속 사진 깊이만 사용한다.
- 네이티브 사진에 빈 영역이 있다고 Depth Anything을 추가 호출해 깊이를 채우던 자동 경로를 제거했다. 네이티브 관측 값/결측 영역을 그대로 보존한다. 깊이 첨부가 아예 없는 automatic 사진의 AI 대체는 유지한다.
- 첨부 심도가 있지만 값/보정 정보가 유효하지 않으면 오류를 돌려준다. 이를 ‘첨부 없음’으로 취급해 조용히 AI로 바꾸지 않는다.
- 센서 심도 사진은 내장 portrait matte가 있으면 기존 경계 보정을 사용한다. 내장 매트가 없다는 이유로 매 사진마다 Vision 분할을 추가 호출하지 않는다. 사용자가 켠 사진 AI 실험의 매트와 이전에 저장한 매트는 계속 사용한다.
- 촬영 패널에 사진 심도로 촬영 후 효과가 적용된다는 안내를 추가했다. 미리보기가 원본처럼 보이는 이유와 AI 프리뷰 선택 위치를 설명한다.

기존 추론/융합 계산 코어·AI 대체·사진/영상/편집 기능을 삭제한 것이 아니다. 새 실험실 옵션을 강제로 끄거나 사용자 저장 설정을 초기화하지 않는다.

### 반복 미리보기 합성 비용 제한

| 심도 프리뷰 조건 | 최대 긴 변 | 최대 효과 프레임률 | 분석 제안 간격 |
|---|---:|---:|---:|
| nominal/fair | 720px | 30fps | 0.5초 |
| 저전력 | 480px | 20fps | 0.5초 |
| serious | 480px | 15fps | 0.5초 |
| critical | 표시 예산480px | 표시 예산10fps | 새 심도 분석·심도 합성 중지 |

LUT만 사용하는 기본 프리뷰의1024px/60fps 예산은 유지한다. 이 값은 preview 효과 예산이며 사진 출력 해상도·영상 파일의 프레임률·센서/광학 AF 설정을 낮추는 변경이 아니다. 기존 추적 제안 간격은 유지한다.

깊이 분석은 구도 분석의 간격 대신 자체 `analysisInterval`을 사용한다. critical에서는 이미 만료 전인 깊이 결과도 PSF 합성에 사용하지 않는다. 이미 실행 중인 Core ML 호출을 강제 종료하는 기능은 아니며, 해당 호출은 기존 완료/세대/만료 검사로 정리된다.

현재 깊이 유효기간은0.75초다. 분석 간격을1초로 벌리면 정적인 장면에서도 프리뷰가 주기적으로 원본으로 돌아갈 수 있어, 열 대응은 우선 출력 크기·합성 fps·native 자동 AI 제거로 하고 활성 분석 간격은0.5초로 제한했다. 실제 추론이 늦거나 움직임이 감지되면 기존 안전 복귀는 유지한다. **기기 발열 감소율/실제 fps를 실측한 수치는 아니다.**

### 네이티브 깊이 정보 저장/복원

`NativeDepthMetadata`에 다음을 기록하고 `SoftwareDepthField`와 결과 recipe의 선택 필드 `nativeDepth`로 전달한다.

- 첨부 깊이의 방향 적용 후 지도 크기, 원본 pixel format, 적용 EXIF orientation.
- `depthDataQuality`, 필터 여부, 절대/상대 accuracy, calibration 존재 여부.
- 가용한 원래 첨부의 intrinsic matrix와 그 reference dimensions.

리사이즈·결측 무효화·수동 교정·기존 융합/시간 처리에서도 원래 첨부의 요약 정보를 보존한다. 이 요약의 intrinsics를 리사이즈된 지도에 그대로 적용하지 않는다. 전체 calibration/왜곡 정보는 변경하지 않은 원본 사진에 남고, 요약만으로 정합을 끝냈다고 주장하지 않는다.

행렬 길이/유한값·지도 크기·orientation·단위 정합을 확인한다. recipe 버전3/4의 추가 선택 필드이므로 기존2/3/4 결과에 필드가 없어도 읽을 수 있다. 렌더링한 색상과 깊이의 실제 재투영·신뢰 경계 정밀화는 N2/N3 후속이다.

### 계측 진입점

기존 추론 대기/추론·매트·실험실·고해상도 export signpost는 유지한다. `Native photo depth decode` 구간과 GPU 캡처용 `PhotoP depth PSF` encoder label을 추가했다. 전체 systemPressure/RSS/전력 기록·기기 trace는 아직 수행하지 않았다. 이 label/CPU 구간을 GPU 실행 시간 실측으로 세지 않는다.

## 2. 검증

- Swift6.0.3 Linux 도구 체인을 공식 배포본에서 `/tmp`에 설치해 **공통 로직164개 통과**. 그중 신규6개는 native/AI 선택·critical 중지·만료보다 짧은 분석 간격·메타데이터 coding/resize/교정·잘못된 calibration/단위 거부·기존 필드 호환을 검사한다.
- 앱/네이티브 테스트 Swift190파일 구문 검사 통과. SDK type checking이나 실행 검증으로 세지 않는다.
- iOS 전용으로 preview 예산 통합1개와 저장→재열기→재편집→필드 없는 구형 recipe 호환1개를 추가했다. **이2개는 Linux에서 실행하지 않았다.** 심도 집중 CI의 선택 목록에 새 policy와 PreviewBudget 클래스를 포함했다.
- 첫 공통 검사 시작 시 새 타입 파일이 아직 Package.swift에 포함되지 않아 컴파일 실패했다. 파일 목록을 연결한 뒤 전체164개가 통과했다. 이후 정책 수정의 집중6개와 최종 전체164개를 재검사했다.
- `git diff --check`·문서 링크 검사 결과는 [08 검증68절](08-STEP-VALIDATION.ko.md#68-네이티브-심도-우선-1차-개발--2026-11-25)과 [당일 일지](development-log/2026-11-25.md)에 기록한다.

새 Xcode/iPhone/Simulator/Core ML/Metal/UI 실행과 실제 iPhone15Pro/iOS27.2 발열·화질 비교는 미수행이다. 새 CI 실행·커밋·푸시도 하지 않았다. 기존 CI 통과 수치를 이 변경의 검증으로 재사용하지 않는다.
