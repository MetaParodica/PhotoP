## 2. Leica LUX 공식 자료에서 확인한 것

[Leica LUX 공식 제품 페이지](https://leica-camera.com/en-int/photography/leica-apps/leica-lux)의 본문은 다음을 설명한다.

- 렌즈의 빛 표현 특성을 디지털로 시뮬레이션한다.
- Noctilux-M 50 f/1.2, Summilux-M 28 f/1.4, Summilux-M 35 f/1.4, Leica I Model A를 예로 든다. 이는 조회 페이지의 예시이며 전체 렌즈 목록·앱 버전별 지원표는 아니다.
- 노출·셔터·ISO·초점·화이트밸런스 수동 제어, RAW/ProRAW 저장을 설명한다.
- 렌즈 표현과 Color/Monochrome/Artist Looks·그레인을 별도 요소로 소개한다.

여기서 도출하는 제품 설계는 **렌즈 프로필과 색 LUT를 분리**하는 것이다. 렌즈 선택은 흐림량·원판 밝기·형태·주변부 특성을 바꾸고, 룩은 색·질감에 관여하게 한다.

확인하지 못한 것:

- Leica 내부 깊이 모델·매팅 모델·학습 데이터·광학 PSF·렌더링 구현. 공식 페이지는 이를 공개하지 않는다.
- 특정 장면에서 Apple 인물 사진이나 PhotoP보다 우수하다는 실측 결과.
- 공식 [튜토리얼](https://manuals.leica-camera.com/lux)은 HTTP HTML을 받았지만 JavaScript 셸이었다. 별도 Chromium 조회는 인증서 신뢰 오류로 완료하지 못했고 TLS 검증을 우회하지 않았다. 튜토리얼 본문을 읽었다고 주장하지 않는다.

렌즈 상표·룩 이름·상용 자산을 복제하지 않는다. 초기에는 PhotoP 독자 프로필 `Natural`, `Portrait`, `Classic`을 제안한다. Focos는 재초점 UX의 향후 비교 대상이지, 이번에 최신 공식 사양이나 앱 실측을 완료한 대상은 아니다.

## 3. 현재 PhotoP와의 차이

현재 소스의 실제 구현:

- `Processing/CaptureResultProcessor.swift`의 `MeasuredDepthEffect`는 사진에 포함된 Depth/Disparity를 `AVDepthData`로 읽고 방향을 맞춘다.
- `Camera/CaptureWorkflowPolicy.swift`의 `DepthBlurPolicy`는 터치 주변 유효 샘플 중앙값, 역깊이 차이 기반 단일 마스크, f값에 따른 경험적 반경을 사용한다.
- 합성은 `CIMaskedVariableBlur`이며 물리 조리개·signed CoC·가림 레이어·머리카락 알파·렌즈형 보케 엔진은 아니다.
- `HighResolutionPhotoProcessor`는 최대64MP/긴 변16384px 파일 기반 타일 처리를 제공한다. 파일 해상도 지원이 같은 해상도의 깊이 디테일을 보장하지 않는다.
- 현재 f값은 PRO의 **소프트웨어 흐림 강도**다. 기존 실시간 Metal 출력은 LUT/보조 분석용이며 심도 실시간 합성을 구현한 것은 아니다.
- 현재 앱에는 인물 효과/시맨틱 매트 요청·AI 단안 깊이 모델·정밀 매팅이 없다.

즉 기존 기능은 유용한 기준선이지만, 최고 수준의 광학 심도 엔진은 새 처리 계층이 필요하다. 기존 원본 보존·LUT·수동 설정 보호는 유지한다.

## 6. Apple 우선·하이브리드 설계

[Apple 깊이 사진 가이드](https://developer.apple.com/documentation/avfoundation/capturing-photos-with-depth)는 상대/절대 정확도를 구분하며 색·깊이를 별도 보관해 촬영 후 효과를 바꿀 수 있다고 설명한다. [인물 매트 가이드](https://developer.apple.com/documentation/avfoundation/configuring-camera-capture-to-collect-a-portrait-effects-matte)는 지원 깊이 구성, 촬영 후 생성, 사람 미검출 시 nil 가능성을 설명한다. 얼굴이 검출되어도 매트 전달은 보장되지 않는다.

권장 입력 순서:

1. 지원되는 사진 깊이·인물/시맨틱 매트.
2. 신뢰도 높은 하드웨어 깊이를 거리 기준점으로 사용.
3. 허용된 경량 단안 깊이로 장면 구조·빈 영역 보완.
4. 알파 매팅·전경색 복원으로 경계 처리.
5. 깊이 부호·가림을 이해하는 독립 Metal 보케 엔진.

`DepthFrame`에는 source, metric/relative 단위, 정확도, 깊이·유효 영역, 보정/크롭/회전/미러링, 타임스탬프를 명시한다. 픽셀별 confidence는 실제 제공되거나 추정한 경우에만 출처와 함께 넣는다. `AVDepthData`의 전체 정확도 플래그를 ARKit의 픽셀별 confidence로 오인하지 않는다.

ARKit LiDAR 장면 깊이와 AVFoundation 사진 깊이는 좌표·시야각·시간·지원 세션이 다르다. 무조건 동시 실행하지 않고, 동기화·외부/내부 보정·지원 조합을 별도 검증한다. 사진 해상도, RAW, 프레임률, 깊이·매트 동시 전달도 각각 확인한다.

iOS 27의 네이티브 AF는 초점 대상 공유에 활용하고, iOS 26+ 네이티브 Cinematic Video는 별도 영상 후보로 평가한다. 이것들이 맞춤형 정지 사진 보케 엔진을 자동으로 대신하는 것은 아니다. 상세 제약은 [26 보고서](26-IOS17-27-CAPABILITY-RESEARCH.ko.md)를 따른다.

## 7. 렌더링 알고리즘

### 7.1 초점과 signed CoC

얇은 렌즈 근사에서 센서면 흐림 직경:

`c(z) = f² / (N × (s − f)) × |1 − s/z|`

f는 가상 초점거리, N은 가상 f값, s는 초점 거리, z는 픽셀 거리다. 일관된 가상 센서 폭으로 픽셀 직경을 계산하고 반경은 절반으로 한다. 전경/배경 부호를 별도로 유지한다. 모든 거리에 같은 단위를 사용한다. 상대 깊이는 metric 값으로 대입하지 않고 별도의 보정·강도 계약을 사용한다.

조리개 변경은 깊이 AI 재실행 없이 CoC·렌더링만 갱신한다. 프리뷰와 최종 사진은 같은 초점·렌즈·해상도 비례식을 사용한다. 물리 조리개가 지원되는 미래 장치에서도 `opticalAperture`와 `simulatedAperture`는 분리한다.

### 7.2 알파·가림·배경 보완

`I = alpha × F + (1 − alpha) × B`를 고려한다. 마스크만 부드럽게 하고 기존 RGB를 쓰면 머리카락의 배경색 오염이 남는다. 불확실 경계 트라이맵 → 알파 복원 → 전경색 오염 완화 → 보완 배경과 합성 순서를 검토한다.

배경 보완은 큰 CoC에 필요한 경계 주변부터 로컬 패치/색 확장으로 수행한다. 가려진 간판·얼굴을 사실처럼 생성하지 않는다. 신뢰도가 낮으면 흐림을 제한한다. 인물 전체를 평면으로 강제하지 않고 눈·얼굴 보존 구간과 실제 내부 깊이를 함께 사용한다.

### 7.3 보케와 색

깊이 레이어와 다중 해상도를 사용하는 gather/scatter 혼합 렌더러를 제안한다. 작은 반경은 높은 해상도, 큰 반경은 낮은 해상도에서 처리하고 깊이 구간을 보간한다. 배경 보케가 앞 물체를 덮지 않게 하고 흐린 전경은 뒤 영역 위로 확장한다. 커버리지·밝기 정규화와 에너지 보존을 검사한다. 전체 이미지에서 `O(W×H×r²)` 대형 원판 연산은 피한다.

Natural은 중립 원형, Portrait는 부드러운 원판 분포, Classic은 조리개 형태·주변부 특성을 제공한다. 캣아이·스월·색수차는 기본 경계 품질 확보 후 추가한다.

처리 순서: 색 관리 디코딩 → 작업용 선형화 → 심도 합성 → SDR 인코딩 → 기존 encoded-sRGB LUT → 그레인/마감. JPEG/HEIF의 톤매핑까지 되돌린다는 주장은 하지 않는다. RAW 현상/HDR 광량 복원은 별도 과제다. 같은 비네팅/번짐을 렌즈와 필름 효과에서 중복 적용하지 않는다.

### 7.4 시간 안정성과 고해상도

깊이·매트는 낮은 빈도, 렌더링은 높은 빈도로 처리한다. 이전 결과를 움직임에 맞춰 이동시키고 신뢰도별 시간 필터를 적용한다. 새 가림 영역, 장면/렌즈/방향 전환, 오래된 프레임은 초기화·만료 처리한다. 빠른 움직임에는 약한 시간 필터를 사용해 잔상을 제한한다.

고해상도는 CoC에 따른 halo, 타일 밖 전경 영향, 전체 이미지 좌표, 레이어별 경계 일관성을 추가 검증한다. 기존 LUT 타일을 그대로 재사용하면 충분하다고 가정하지 않는다. 결과·깊이·매트·recipe/schema/source hash를 원본과 별도로 원자 저장하고 재시작 후 재생성한다.

## 8. 모듈과 UI

제안 모듈: `DepthSourceCoordinator`, `DepthFrame`, `DepthFusionEngine`, `MatteRefinementEngine`, `DepthTemporalFilter`, `FocusPlaneController`, `LensProfile`, `CircleOfConfusion`, `OcclusionAwareBokehRenderer`, `DepthRenderRecipe`.

`CameraService`는 장치·캡처, `CameraModel`은 사용자 상태, 처리 모듈은 렌더링을 소유한다. AF/AE 요청과 가상 재초점은 구분하고 사용자 선택 target ID/좌표만 공유한다. 보케 조절이 ISO·셔터·AF 잠금을 몰래 바꾸지 않는다.

촬영 UI는 기존 하단 f값·렌즈 프로필·원본 비교를 사용한다. 촬영 후 초점·가상 f값·프로필을 비파괴 변경한다. 무효 깊이는 제한/원본 유지/이유 안내 중 명시적 정책으로 처리한다. 낮아진 출력 해상도를 숨기거나 측정하지 않은 깊이를 센서 결과처럼 표시하지 않는다.

## 10. 평가·성능·일정

성능은 **목표이며 미측정**이다. 상위 기기720p~1080p/30fps, 깊이·매트5~15Hz 검토, 렌더러 p95 약10ms·전체 프리뷰 p95 150ms 이내 지향, 12MP 수 초 처리를 초기 기준으로 삼는다. 메모리는 기기별 예산을 정하고 전체 고해상도 RGBA 중복을 피한다. 60fps/48MP 실시간 보장은 하지 않는다.

평가 세트는 역광·야간·다양한 피부/머리색·반려동물·유리·식물·전경·다중 인물·움직임을 포함한다. 동의 받은 사진만 보관하고 평가 사진을 자동 학습에 전용하지 않는다. 약100장 실패 세트에서 시작해 수백 장과 짧은 영상으로 확장한다.

동일 입력 비교와 앱별 촬영 비교를 분리한다. 실제 DSLR은 거리·화각을 맞춘 광학 참조이지, 서로 다른 센서의 픽셀 정답으로 취급하지 않는다. 합성 장면의 알파/깊이 정답, 경계 누출·디테일·시간 잔상·밝기·실패율·블라인드 선호도·기기 지연/발열을 함께 평가한다. 단일 PSNR/미학 점수로 최고 품질을 주장하지 않는다.

카메라/Metal 경험자2~3명과 Mac·여러 iPhone을 가정한 거친 추정: 조사/검증2~3주, 정지 사진 코어6~10주, 렌즈/실시간5~8주, 고해상도/인수3~6주. 일부 병행 가능하지만 수개월 규모이며 확정 일정이 아니다.

## 11. 이번 단계의 완료와 미완료

완료: 원격 연결·main 기준 확인, 기존 코드 읽기, 공식 웹 문서 및 일부 공개 소스 직접 검토, 계획 저장.

미완료: 경쟁 앱 직접 촬영·정량 비교, 가중치/전 의존성 최종 권리 감사, 모델 실행/변환, iOS17~27 SDK 빌드, 실제 지원 기기 조사, 심도 코드 구현. 이 보고서만 저장한 상태에서 기존 심도 기능을 업그레이드했다고 표시하지 않는다.
