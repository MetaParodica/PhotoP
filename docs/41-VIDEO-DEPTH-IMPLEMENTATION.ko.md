# 사진·영상 심도와 선택 피사체 추적 구현

2026-11-19 사용자 요청 기준. 조사 [39](39-VIDEO-DEPTH-AND-TRACKING-RESEARCH.ko.md) → 사전 계획 [40](40-VIDEO-DEPTH-IMPLEMENTATION-PLAN.ko.md) → 이 구현 순서다. 실제 빌드/테스트/게시 상태는 [08](08-STEP-VALIDATION.ko.md)와 [개발 일지](development-log/2026-11-19.md)에 정확한 SHA로 기록한다.

## 사용 방법

- PRO 사진의 f값 패널에서 **선택 피사체 추적**을 켜고 물체/인물/얼굴을 고른 뒤 화면을 터치한다. 구도 추천 AI를 켤 필요가 없다. 신뢰도가 확보된 대상만 초록 박스로 표시하고 심도 초점과 선택 매트를 갱신한다.
- VIDEO 레일에도 f값 패널을 추가했다. **영상 AI 심도**를 켜면 소프트웨어 미리보기를 연결하고 녹화 원본은 그대로 저장한다. 종료 후 별도 심도 MOV/recipe를 생성한다. 녹화 중 f값/프로필/새 터치 변경은 설정 시각부터 기록한다.
- 영상 보관함 → 원본 열기 → **AI 심도 편집 · 원본 보존**에서 첫 화면을 터치해 초점/추적 대상을 지정하고 f값/보케/품질을 바꿔 별도 영상을 만든다. 저장된 결과를 다시 열어 원본 비교·공유·Photos 저장이 가능하다.
- 진행/취소/실패를 표시하고 실패해도 원본을 유지한다. 다른 작업이 처리 중이면 추가 작업을 무제한 대기시키지 않고 원본/심도 설정을 보관한다. 자동 처리는 앱이 실행 중일 때 수행하며 앱 종료 후 자동 재개 기능은 없다. 보관함에서 다시 처리할 수 있다.

## 공통 대상 추적

- `SubjectTrackingPolicy`는 top-left 정규화 좌표, 대상 UUID/generation/단조 시간, confidence·IoU·이동/면적 변화와 연속2개 강한 관측을 검사한다. 약한 관측과 추적 중 상태를 구분하며 0.45초보다 오래된 결과는 초점/흐림/박스에 사용하지 않는다. 0.8초 이상 관측 공백/대상 놓침 뒤에는 재선택한다.
- `SubjectTrackingVisionEngine`은 Apple Vision 물체 시퀀스 추적을 사용한다. 인물/얼굴 모드는 처음 누른 위치를 포함하는 검출만 선택하며 주변의 다른 사람을 자동 대체하지 않는다. 얼굴 검출은 신원 인식이 아니다. 최대640px 분석이며 실제 영상 출력 해상도를 낮추는 설정이 아니다.
- live 분석은 캡처/render queue 밖에서 한 번에1개만 처리한다. 열 budget이 무한대로 분석 중지를 지시하면 추적도 중지한다. 전역 추론 게이트가 바쁘면 낡은 결과로 강행하지 않는다. 렌즈/방향/모드/비활성화 시 이전 결과를 무효화한다.
- AF 추종은 실제 `AVCaptureVideoPreviewLayer`의 이미지→장치 좌표 변환을 사용한다. 2Hz/이동량 제한을 두며 AF-C에서만 초점을 바꾼다. MF·사용자/장치 잠금·AF-S·네이티브 추적을 덮어쓰거나 노출을 바꾸지 않는다. 고정 거리(m)를 추측해 표시하지 않는다.
- 사진 저장 초점과 영상 설정은 미러 프리뷰를 원본 좌표로 바꾼다. 영상은 녹화 시작 때 고정한 방향과 현재 프리뷰 방향 차이도 변환한다. 회전/렌즈 변경은 현재 추적을 해제하므로 새 대상을 터치한다.

## 실제 영상 출력

- `VideoDepthProcessor`는 원본을 검사하고 해시를 기록한 뒤 AVAssetReader→기존 Core ML Depth Anything V2 Small→선택 매트→사진과 같은 `NaturalDepthEngine`→AVAssetWriter로 처리한다. 별도 결과의 해시/레시피를 기록하고 pending 폴더의 완성 결과만 원자 게시한다.
- 파생 영상의 픽셀 경로는8비트 BGRA SDR이다. 원본 bytes는 보존하지만10비트 SDR의 비트 심도까지 파생물에 유지하는 경로는 아직 구현하지 않았다.
- SDR H.264/HEVC, 최소16px·최대4096px/9.4MP, 60fps, 10분, 비디오1트랙/오디오0~1트랙 범위다. 기존 4K 촬영 해상도를 자동 축소하지 않고 원래 코덱·원본 이상 목표 bitrate(최대240Mbps)를 요청한다. 인코더의 실제 지원을 검사하며 지원하지 않으면 원본을 남기고 실패를 알린다. 무손실 출력이라고 주장하지 않는다.
- 원래 각 프레임의 PTS를 사용하며 임의 index/fps로 재타이밍하지 않는다. 회전은 실제 출력 픽셀에 적용하고 파일 transform은 identity다. 오디오는 압축 sample을 passthrough하여 다시 인코딩하지 않는다. 다음 오디오/비디오 PTS 순으로 읽고 writer readiness/timeout/cancellation을 검사한다.
- 매 프레임 새로운 깊이를 추정한다. 상대 깊이를 단순 평균하지 않는다. 시계열 척도 정합/메모리 segmentation 모델은 후속 과제이며 시간적 깜빡임이 완전히 해결됐다고 주장하지 않는다.
- 추적이 불확실하거나 깊이 합성이 실패한 프레임은 원본을 유지하고 개수를 recipe/앱에 알린다. 적용 프레임이0개면 성공으로 저장하지 않는다. 입력/쓰기/무결성 오류는 작업 전체를 실패시킨다.
- 결과 메타데이터에는 AI 심도 처리 설명을 기록하고 원본 GPS/장치 metadata를 복사하지 않는다. 공유는 이 파생 파일을 사용한다. 원본 bytes/hash는 변경하지 않는다. 별도 JSON에는 모델/처리/품질·초점/설정 시간과 원본/결과 해시·프레임 수를 기록한다.
- 한 번에1개 작업이며 프레임 전체 배열을 보관하지 않는다. 고품질16쌍/균형8쌍 샘플을 사용한다. 기존 미리보기 축소·열 제한과 완성 출력 품질은 별개다. 실제 iPhone15Pro의4K 메모리/열/속도 인수는 아직 필요하다.
