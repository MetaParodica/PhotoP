# 개발 일지

2026-11-18 사용자 요청으로 시작한다. **그날 수행한 개발·조사·문서·검증·실패 대응·저장소 작업을 날짜별 한 파일에 누적한다.** 새 작업마다 별도의 일지를 만들거나 기존 당일 내용을 덮어쓰지 않는다.

## 파일 구성

```text
docs/development-log/
  README.md             # 작성 규칙과 날짜별 색인
  TEMPLATE.md           # 새 날짜 파일의 기본 양식
  2026-11-18.md          # 해당 날짜의 누적 작업
```

- 파일명은 `YYYY-MM-DD.md`, 본문은 한국어로 작성한다.
- 사용자 지정 시간대가 있으면 우선하고, 없으면 클라이언트 시간대(없으면 환경 시간대)를 따른다. 현재 기준은 **Asia/Seoul(KST)**이며 각 파일에도 표시한다. 이전 UTC 기록은 원래 시각을 보존하고 기준 변경을 명시한다. 시각을 알 수 없으면 추정하지 말고 미기록으로 둔다.
- 작업 시작 시 그날 파일을 먼저 읽는다. 파일이 없으면 [템플릿](TEMPLATE.md)을 복사하고 실제 날짜·시간대·기준 ref를 채운다.
- 작업을 진행하며 항목을 추가하고 **완료 답변 전에 현재까지의 내용을 정리한다.** 같은 날의 후속 작업도 같은 파일에 이어 쓴다. 자정을 넘으면 다음 날짜 파일에 이어지는 작업임을 남긴다.
- 날짜가 지나고 미완료 작업이 남으면 다음 일지에서 이전 항목을 연결한다. 과거 날짜의 오류를 바로잡을 때는 정정 내용과 정정일을 남긴다.
- 색인에 새 날짜와 핵심 작업을 추가한다. 현재 날짜는 하루가 끝났다고 단정하지 않고 “현재까지 정리”로 표시할 수 있다.

## 기록할 내용

| 항목 | 작성 기준 |
|---|---|
| 요청·결정 | 사용자가 요청한 작업, 확정/보류한 범위. 기존 결정을 새로 내린 것처럼 쓰지 않음 |
| 수행 내용 | 무엇을 왜 바꿨는지, 조사로 확인한 사실, 변경 파일과 결과 |
| 실패·수정 | 오류/막힌 이유, 확인한 근거, 수정 또는 보류 결과 |
| 검증 | 명령·CI URL·대상 SHA·환경·통과/실패/skip/미실행과 이유 |
| 저장소 상태 | 브랜치·기준 커밋, 실제 생성한 커밋/푸시/머지 여부. 미커밋이면 명시 |
| 남은 일 | 다음 작업, 실기기 인수, 필요한 자료·결정 |

같은 날 여러 요청이 있으면 작업별 소제목을 추가한다. 로그 원문 전체를 복사하기보다 재현에 필요한 명령·오류·결과와 원본 자료 링크를 남긴다. 최종 통과만 남기지 말고 중요한 실패/해결 과정도 보존한다.

**기록의 근거를 구분한다.** 이번 작업에서 실행한 검사, 이미 완료된 CI를 열어 확인한 결과, 이전 작업을 Git/문서로 회고한 내용은 각각 표시한다. 커밋 시각을 실제 작업 시작/종료 시각으로 간주하지 않는다. 일지 자신의 아직 없는 커밋 SHA를 추측해 채우지 않는다.

기능 상세는 주제별 문서, 과제 상태는 [32 백로그](../32-NEXT-TASK-BACKLOG.ko.md), 검증의 상세 이력은 [08 단계별 기록](../08-STEP-VALIDATION.ko.md)에 유지한다. 일지는 이를 날짜별로 찾아갈 수 있는 작업 기록이며, 기존 문서를 대체하지 않는다. 매 작업 종료 시 작성하는 규칙이며 별도 예약 실행이나 자동 커밋/푸시를 설정한 것은 아니다.
