# AI Composition — Phase 1 구현 및 검증 기록

기준: `bddf682`(main에 푸시된 촬영 개선 코드), 2026-10-22.

후속 사용자 요청에 따른 화면 배치·LUT 동작·PRO 심도·장노출 시간 변경은 [19 문서](19-FULLSCREEN-CAPTURE-WORKFLOW.ko.md)를 우선한다. 이 문서는 AI Phase 1 통합 당시의 검증 기록이다.

추가 후속 요청인 **전체 Phase 구현**에 따른 Phase 2–5 코드 통합과 현재 검증 상태는 [20 문서](20-INTELLIGENT-CAMERA-ALL-PHASES.ko.md)를 우선한다. 아래 후속 단계 보류·RAW 라이브 제한 설명은 당시 기록이며 현재 코드와 다를 수 있다.

첨부 개발 지시서의 Phase 0 분석 후 **Phase 1 코드 통합**을 진행했다. 실제 iPhone 영상 확인이 완료 조건이므로, **Phase 1 전체 완료 또는 후속 Phase 검증 완료를 주장하지 않는다.** 이번 변경은 로컬 작업 트리이며 별도 커밋·푸시는 하지 않았다.

## 기존 구조 및 변경 범위

- `CameraService`: 직렬 큐가 AVFoundation 세션·렌즈·설정·촬영을 소유한다. 사진/영상 저장 경로는 유지한다.
- `LiveLUTPreview`: 기존 BGRA 프레임 출력과 Metal 프리뷰를 재사용한다. 별도 카메라 세션이나 프레임 출력을 추가하지 않는다.
- `CompositionAnalyzer`: 기존 Vision 장면 분석·세대 무효화·한 작업 제한을 확장한다.
- `CameraModel`: MainActor 상태 발행과 오래된 이벤트 거부를 재사용한다.
- `CameraPreview`: 기존 네이티브 탭/길게 누르기/핀치와 AVFoundation 좌표 변환을 유지한다.
- `CameraView`/`CameraQuickControls`: 기존 하단 조절 패널, 재질 디자인, 수동 구도·인물 실루엣·룩을 유지한다.

성공 기준은 실제 검출 프레임에 근거한 인물 박스/선택/삼분할 목표 갱신, 오래된 결과 제거, 안정화된 정렬 판정, 기존 촬영 제어와의 공존이다. 실기기 검증 전에는 추론 속도·정확도·촬영 안정성을 보장하지 않는다.

## 구현한 기능

- 모든 AI 장면에서 `VNDetectHumanRectanglesRequest`와 `VNDetectFaceRectanglesRequest`를 실행한다. 인물 안의 얼굴을 연결하고, 몸 검출이 없는 클로즈업은 얼굴 영역을 사용한다. 표시는 최대 12개다. 얼굴 중심은 눈높이·시선 추정이 아니다.
- `CompositionTracking.swift`: 검출 순서와 독립적인 IoU/거리 기반 1:1 대응, 작은 흔들림 평활화, 빠른 이동 시 지연 감소, 0.8초 이내 일시 가림 복구를 구현한다. 누락된 박스는 화면에 남기지 않는다. 외형/생체 식별이 아니므로 교차·가림·급격한 이동 후 동일 인물 식별은 보장하지 않는다.
- 자동으로 큰 인물 영역을 선택하되 잠깐 놓친 사이 다른 인물로 바꾸지 않는다. 사용자가 선택한 인물이 사라지면 다른 인물로 몰래 전환하지 않고 재선택을 안내한다.
- 화면 탭으로 검출 인물을 선택하면서 기존 AF/AE도 수행한다. 길게 누르기는 기존 잠금만 수행한다. AI 자체는 ISO·셔터·EV·초점·줌을 자동 변경하지 않는다.
- 얼굴 중심 또는 인물 중심을 기준으로 가까운/왼쪽/오른쪽 삼분할 목표를 선택한다. 목표 방향은 **화면 안의 이동 방향**이며 사용자의 실제 이동이나 카메라 회전 방향을 단정하지 않는다. 목표를 바꿔도 명시적으로 선택한 인물을 유지한다.
- 노란 선택 박스, 청록 다른 인물 박스, 흰 목표 박스·중심점·화살표, 초록 정렬 완료를 별도 오버레이로 표시한다. 저장 사진·영상에는 합성하지 않는다.
- 인물 전체가 밖으로 잘리는 목표는 제한한다. 현재 인물 크기로 삼분할 배치가 불가능하면 잘못된 완료 판정 대신 제한을 안내한다.
- 짧은 변 기준 정규화 오차 4.5% 이내에서 0.6초 유지해야 정렬된다. 7.5% 밖에서 해제하며 분석 간격이 0.45초를 넘거나 인물이 누락되면 유지 시간을 다시 센다. 완료 햅틱은 한 번만 요청하고 3초 재발행 제한을 둔다. 기기/시스템 설정에 따른 실제 진동은 미검증이다.
- 하단 레일의 **AI** 버튼으로 즉시 표시/숨김, 길게 눌러 목표/설정 선택, 구도 패널에서 대상 선택·자동 선택 복귀를 제공한다. VoiceOver 이름·상태·선택 버튼을 제공하며 5Hz 자동 음성 알림은 하지 않는다.

## 프레임·좌표·안정성 계약

1. 원본 프리뷰와 독립된 utility 큐에서 최대 640px로 축소하고 Vision을 실행한다. 진행 중인 분석은 하나이며 다음 프레임은 쌓지 않는다.
2. 정상 예산은 최대 5Hz, 저전력/심각 발열 예산은 최대 2.5Hz, 임계 발열에서는 새 분석을 중지한다. 이는 상한이며 실제 측정 FPS가 아니다. 기존 Metal 프리뷰/히스토그램 예산은 유지한다.
3. 시작 후 0.65초를 초과해 끝난 분석은 버린다. UI도 0.65초 이후 박스·목표·완료 상태를 숨긴다. 오래된 일반 구도 검출도 같은 만료 기준으로 변경했다.
4. 분석 입력 픽셀은 기존 연결에서 회전/전면 미러링된 상태다. Vision의 하단 원점 박스만 상단 원점으로 변환하며 미러링을 두 번 적용하지 않는다.
5. 화면 표시는 기존 `GuideGeometry.imageRect`의 fit/fill 변환을 재사용한다. 탭은 공식 `AVCaptureVideoPreviewLayer.layerRectConverted`가 반환한 실제 영상 영역으로 역변환한다. 이미지 밖 탭은 대상 선택에 사용하지 않는다.
6. 회전/줌/렌즈/세션 변경 때 오래된 분석 세대와 선택·정렬을 무효화한다. 앱 비활성화와 프리뷰 해제 때 상태를 지우며 늦게 도착한 결과를 거부한다.
7. 기존 장노출은 분석 프리뷰를 해제한 뒤 합성을 수행하고 종료 후 복구한다. 영상 분석은 장치가 기존 movie/data 동시 출력을 허용할 때만 가능하다. RAW·브래킷의 기존 라이브 프리뷰 제한은 유지한다.
8. 선택적 포즈/직사각형/수평선/saliency 실패가 성공한 인물 검출을 삭제하지 않도록 분리했다. 인물 분석 실패 시에는 수동 촬영을 유지하고 분석 실패 안내를 표시한다.

삼분할 기준은 분석/촬영 이미지 전체다. 기존 1:1·16:9는 여전히 저장 크롭이 아닌 수동 프레이밍 가이드이며, AI 목표를 그 별도 마스크 기준으로 재계산하지 않는다. 프리뷰 fill에서 잘린 검출 표시는 화면 경계에서 클립된다. 센서·프리뷰·안정화 스트림의 실제 화각 일치는 실기기 확인이 필요하다.

## 실제 검증 결과

- Swift 6.0.3/Linux, Swift 5 언어 모드·핵심 타깃 strict concurrency complete: **동일 프로덕션 핵심 소스를 컴파일하고 XCTest 17개 실행, 실패 0개**. 최초 컴파일에서 중첩 삼항식의 타입 추론 시간 초과를 확인해 명시적 switch로 수정한 뒤 통과했다.
- 테스트 범위: 단일/복수 인물, 검출 순서 변경, 작은 흔들림·빠른 이동, 가림·추적 만료, 잘못된 입력/시간, 겹치는 박스 탭, 명시적 선택 유지·실패, 목표 변경 시 선택 유지, 자동 선택 안정성, 얼굴 중심 목표, 방향 문구, 잘리지 않는 목표, 오래된 결과·세대 변경, 정렬 유지·히스테리시스·햅틱 제한, 가로/세로·미러링·fit/fill 좌표 왕복.
- 기존 Python 테스트 **17개 통과**. LUT 검사: 승인 자산 5개 무결성 통과, 기존 외부 자산 25개 무결성 통과(권리 미확인 상태는 그대로이며 승인을 뜻하지 않음).
- iOS Swift 소스 **112개**를 Swift frontend로 구문 검사했다. 이것은 SDK 타입 검사·링크·앱 빌드가 아니다.
- `git diff --check` 통과.
- iOS 전용 분석 예산 테스트 1개, AI 켜기/끄기·시뮬레이터의 가짜 인물 방지 UI 테스트 1개 및 실제 앱 스크린샷 첨부 코드를 추가했다. **여기서는 실행하지 않았다.**
- CI에 portable `swift test`를 추가했다. **이번 변경의 iOS CI 실행/성공 기록은 아직 없다.** 기존 CI 성공을 재사용하지 않는다.
- Xcode/iOS SDK/Simulator/iPhone이 없으므로 앱 빌드, Vision 실영상 검출, 실제 카메라 저장, 화면 캡처, 햅틱, FPS/추론 시간/배터리/발열 측정은 미수행이다. 목업이나 합성 이미지를 실제 앱 화면으로 제공하지 않았다.

재현: Swift 설치 환경의 저장소 루트에서 `swift test`. Xcode 검증은 기존 `ios/project.yml` → `xcodegen generate` → iPhone SDK build 및 XCTest/UI 테스트를 사용한다.

## 실기기 인수 검사와 남은 단계

- [ ] 인물 1명/2명 이상, 클로즈업/전신·가림·교차·빠른 이동에서 실제 박스/선택 일치.
- [ ] 전면/후면·렌즈 전환·핀치 줌·세로/양쪽 가로·영상 fit/fill에서 오버레이/탭 일치.
- [ ] 이동 중 650ms를 넘긴 박스/완료 표시가 남지 않는지, 발열 중 대기 표시와 복구.
- [ ] 정렬 유지·해제·재정렬 햅틱과 VoiceOver 조작.
- [ ] AUTO/PRO의 ISO/셔터/EV/초점/잠금과 가이드 선택 공존.
- [ ] 권한 거부·중단·백그라운드·재시작·분석 실패에서 카메라/저장 정상 동작.
- [ ] 가이드 ON/OFF의 실제 FPS·추론 시간·메모리·발열 비교, 사진/영상 저장 및 장노출 복구.
- [ ] 실제 빌드의 AI ON/OFF 화면 확보. 시뮬레이터 UI 화면은 실카메라 검증과 구분.

지시서에 따라 위 Phase 1의 실영상 검증 전에 후속 범위를 동시에 확대하지 않았다. 촬영 의도별 자동 추천/새 구도 엔진(Phase 2), 스마트 줌·노출·Core Motion 코치(Phase 3), 촬영 후 분석·이전 경험 학습(Phase 4), 전체 모드의 실기기 호환 검증(Phase 5)은 남아 있다. 기존 수동 프리셋·포즈·수평선 분석이 존재한다는 이유로 이 후속 요구를 완료 처리하지 않는다. 동물/음식/제품 등 범용 객체 인식, 눈·시선 추정, 미학 점수도 구현하지 않았다.
