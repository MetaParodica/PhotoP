# 추가 결정 필요 사항 보고

> **후속 사용자 결정 반영:** 이 문서는 결정 전 검토 기록이다. 이후 사용자가 AI 메타데이터/앱 내 공지, 공유본 위치 제거·원본 내보내기 위치 보존, 품질 우선 출력을 확정했고 구형3개는 원격 태그 백업 후 삭제했다. 현행 기준과 실제 정리 결과는 [36 기록](36-USER-DECISIONS-AND-BRANCH-CLEANUP.ko.md)을 따른다. 아래 “미결정/제안/유지”는 작성 당시 상태다.

2026-11-18. 확인 기준: 원격 main **`2c1a7b3`**, [32 백로그](32-NEXT-TASK-BACKLOG.ko.md), [33 구현 기록](33-IOS18-FUSION-SCOPES.ko.md), [34 온보딩](34-DEVELOPER-ONBOARDING.ko.md)과 현재 소스.

**기존 문서에 명시된 미결정은2건이다.** 아래 권장안은 이번 보고의 제안이며 사용자의 새 결정이나 구현 완료로 기록하지 않는다. 두 항목 모두 전체 개발을 멈출 이유는 없고, 해당 기능/정리를 진행할 때 범위를 확정하면 된다.

## 1. 이미 확정되어 유지할 내용

- 최소 iOS18, 파생 사진·영상은 SDR.
- HDR 출력/게인맵 생성·보존, Log/HDR 영상, C2PA는 도입하지 않음.
- 위치 태깅은 기본 활성화로 개발하되 권한 거부 시 위치 없이 촬영. 원본 생성 시점에 처리하고 저장 후 원본을 수정하지 않음.
- 원본 bytes/hash 보존, 지원하지 않는 조합의 명시적 거부, 파생물 별도 저장.
- 날짜별 개발 일지는 같은 날짜 파일에 누적. 현재 환경의 UTC를 사용하며 별도 변경 지시 전 유지.

근거: [CLAUDE.md](../CLAUDE.md), [32 문서 7절](32-NEXT-TASK-BACKLOG.ko.md#7-사용자-결정), [개발 일지 규칙](development-log/README.md). 이 항목들을 재승인할 필요는 없다.

## 2. 기존에 명시적으로 남아 있는 결정

| 항목 | 필요한 결정 | 권장안 | 결정이 필요한 시점 |
|---|---|---|---|
| D01 — AI 처리 결과 표기 | 어떤 처리에 어떤 문구를 어디에 표시할지. 결과 정보/파생물 메타데이터/사진 픽셀 워터마크 여부 | **결과 정보와 지원되는 파생물 메타데이터에 처리 종류를 표시**하고 사진 픽셀 워터마크는 기본으로 넣지 않는 방향. 예: “AI 추정 심도 적용”, “AI 확대 처리”. 단순 구도 분석·일반 LUT·SDR 융합까지 일괄 “AI 생성 사진”으로 표시하지 않음 | 새 표기 정책 또는 F11 초해상 결과를 구현할 때. 현재 미결정 상태 유지 |
| D02 — 원격 브랜치 정리 | 아래3개를 유지/백업/삭제할지 | **지금은 유지**. 정리 요청이 있을 때 최신 main과의 미반영 차이·필요한 백업을 확인한 뒤 삭제 범위 결정. 기능 개발과 별개로 진행 가능 | 원격 정리 작업을 할 때 |

## 3. 추가로 선택하면 좋은 제품 기본값·인수 준비

아래3건은 기존 문서에서 명시적 미결정으로 등록된2건과 **별개의 추가 제안**이다. 권장값으로 설계안을 준비할 수 있으며 개발 전체의 필수 승인 절차로 만들지 않는다.

| 항목 | 추가 선택 내용 | 권장 방향 |
|---|---|---|
| P01 — 위치 포함 공유 | 촬영 원본에 위치를 기록하는 결정과 별도로, 공유본에 위치를 포함할지와 기본값 | **공유 전 위치 포함 여부를 선택**, 기본 공유본은 위치를 제거한 별도 사본으로 제안. 앱 원본과 보관용 위치 정보는 유지. 실제 지원 포맷·Photos/영상 경로는 F12 API 확인 후 설계 |
| P02 — 편집/파생 출력 형식 | F4에서 JPEG·SDR HEIC 중 기본값과 선택 제공 방식 | **현재 JPEG 기본을 유지**, SDR HEIC는 선택 옵션으로 추가하는 방향. 원본 촬영 포맷 설정과 구분하고 HDR/게인맵은 포함하지 않음 |
| P03 — 실기기 인수 준비 | 확보 가능한 실제 기기/OS, 촬영·평가 자료와 수행 계획 | **iOS18 지원 저사양급·일반급·LiDAR Pro 각1종 이상**에서 기준선 수집. 기존 심도100장/블라인드 기준과 F1 약30세트를 유지. p95·메모리·열의 수치 목표는 측정 뒤 확정 |

P01은 “위치 태깅 기본 활성화”를 취소하는 제안이 아니다. 촬영/보관과 외부 공유의 동작을 구분하는 선택이다. 현재 앱은 위치 권한 요청/수집 코드가 없고, 리뷰는 현재 파일을 ShareLink로 공유한다. 위치를 제거한 공유 사본 기능이 이미 존재한다고 표시하지 않는다.

P02는 현재 파생 JPEG 경로를 기본으로 유지할 수 있으므로 F4 이전 개발을 막지 않는다. P03은 최소OS를 다시 정하자는 뜻이 아니며 실제 장비/자료 확보가 필요한 인수 계획이다. 측정 없이 임의의 FPS·p95나 경쟁 앱 동급을 보증하지 않는다.

## 4. 사용자 결정보다 기술 확인·실행이 필요한 일

- **F12 공식 API 계약 재확인:** 사진·DNG·영상·Photos에서 생성 시점 위치 전달, 권한 거부/정확도/오래된 위치/취소 처리를 확인하는 기술 작업이다. 기존 태깅 결정을 다시 물을 이유는 없다. 이전 문서 본문403 기록을 현재 환경의 영구 차단으로 간주하지 않는다. 이번 보고에서는 API 본문을 재조회하지 않았다.
- **F1/F2 실기기 검증:** 구현/자동 회귀 통과와 화질·발열·지연·영상 동시 출력 인수는 다르다. 장비/자료가 준비되면 기존 기준으로 진행한다.
- **F4 메타데이터 처리:** 파생물의 실제 색공간·방향·해상도와 일치하도록 검증해야 한다. 원본 ICC/EXIF를 무조건 복사하는 문제로 다루지 않으며 현재 SDR/sRGB 계약을 임의 변경하지 않는다.
- **B02/B03/B06/B07/S01 설계:** 추론 스케줄러·열 제어·GPU 타일·후처리 큐의 구체적 구현은 기준선/코드 검토로 정할 기술 항목이다. 매 구현 세부사항을 사용자 승인 항목으로 늘리지 않는다.
- **다음 개발 순서:** 기존32 백로그의 F12 확인 → F3/F4/F8 및 성능/구조 과제를 기본으로 유지할 수 있다. 이번 보고로 기존 우선순위를 임의 변경하지 않는다.
