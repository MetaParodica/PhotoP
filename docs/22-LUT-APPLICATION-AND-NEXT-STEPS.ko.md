# LUT 적용 점검·수정 및 추가 개발 필요사항

2026-10-23 KST. 기준 원격 main `736cdcc`. 사용자 요청으로 기존 64MP·외부 LUT 권한 변경과 아래 LUT 수정사항을 함께 커밋/푸시하고 main에 병합한다. 실제 반영 커밋은 대화의 Git 결과로 별도 보고한다. 이 문서의 검증 결과는 로컬 작업 트리 검사이며 iPhone/CI 통과를 의미하지 않는다.

### 효과가 약한 경우의 처리

- `LookEffectAssessment`는5×5×5 표준 encoded RGB 샘플에서 실제 CPU LUT 보간·현재 강도를 적용해 평균 채널 변화량을 확인한다. 이 값은 사진 품질/미학 점수나 특정 장면의 체감 차이가 아니다. 카메라 프레임 또는 LUT 예시 이미지를 렌더하지 않는다.
- 강도0%에 다른 효과도 없으면 모두 꺼졌다고 표시한다. 색상표가 항등에 가깝지만 입자/공간 효과가 있으면 **공간 효과 중심**이라고 표시한다. 색상 변화가 표본 평균1/255 미만이고 다른 효과가 없으면 **변화가 작은 LUT**라는 안내를 제공한다.
- 모든 LUT를 임의로 강하게 만들거나 색 프로파일·기존 수치표를 바꾸지 않았다. 자연스러운 룩, 중립 기술 변환, 회색/단색 장면은 정상 적용되어도 차이가 작을 수 있다. 실제 장면의 차이는 원본과 효과 결과를 비교해야 한다.
- **카메라 프리뷰는 이전 사용자 요청대로 무보정**이다. 이것 자체는 LUT 결과 생성 실패가 아니다. 촬영 화면/룩 패널에서 결과 전용 적용·강도·RAW/DNG 또는 영상 미적용을 표시한다.
- 권한이 확인된 외부25개의 원본·출처·수치표를 유지한다. WDR 출력 프로파일 미확인1개는 여전히 적용하지 않는다. 권한 확인으로 색 프로파일까지 추정하지 않는다.

## 저장 호환성과 경계

- v1 즐겨찾기와 기존 편집/프리셋 레시피는 계속 읽는다. 새 v2 레코드에는 cube hash와 효과 설정이 필수이며 버전·범위·설정 기반ID·cube hash를 검증한다. 바뀐 파일을 덮어써서 복구하지 않고 오류로 반환한다.
- 촬영 당시 룩은 현재 세션의 최신 촬영 묶음에 연결한다. 이후 다른 룩을 선택해도 이전 촬영의 설정을 바꾸지 않는다. 별도 결과를 편집할 때는 대응 원본에서 LUT를 복원하므로 색 보정 중복을 방지한다.
- 편집기의 기존 기능은 LUT/필름 편집이다. 사진 깊이를 조정하는 편집 UI를 새로 추가한 것은 아니므로 촬영 때 생성한 심도 결과는 별도 보존되며, 편집기에서 원본을 열어 LUT를 복원한다고 심도 마스크 편집까지 제공하는 것은 아니다.
- 구형 즐겨찾기에 저장되지 않은 임의 설정이나 이미 충돌로 소실된 다른 공간 룩 이름까지 복원할 수는 없다. 내장 공간 룩은 다시 선택해 새 즐겨찾기로 저장할 수 있다.

## 검증

- Swift 6.0.3/Linux portable XCTest **76개 통과**: 기존69개+색 변화 진단5개+선택 사진/원본 라우팅2개. 실제 프로덕션 CubeLUT 보간을 사용하며 항등/채널 교환/약한 색 이동/강도0/공간 효과/잘못된 입력과 브래킷·파생물 대응을 검사한다.
- Python **19개 통과**, LUT5+25개 원본 무결성·권한 레코드 검사 통과. 원본 LUT 파일은 변경하지 않았다.
- Swift 전체 구문 검사 및 `git diff --check` 통과. 이 검사는 iOS SDK 타입 검사·Metal 컴파일·카메라 실행이 아니다.
- iOS 앱 테스트에 즐겨찾기 v2 설정 보존/공간 carrier 충돌 방지/구형 복구/변조 거부4개, 명백한 비항등 LUT의 촬영 결과 픽셀 변화·원본 보존1개를 추가했다. 이전 고해상도/권한 테스트도 함께 포함한다. **Xcode/iOS SDK/Metal runtime이 없어 실행하지 못했다.**
- 최신 GitHub Actions는 `gh run list`가403을 반환하여 상태를 확인하지 못했다. 과거 CI 성공을 이번 변경의 증거로 사용하지 않는다. 실제 iPhone에서 발생한 모든 무효과 사례가 재현/해결됐다고 주장하지 않는다.
