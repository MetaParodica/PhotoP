# PhotoP — DSLR급 차세대 컴퓨테이셔널 심도 엔진 고도화 개발 지시서

## 0. 역할과 최종 목표

당신은 iOS 카메라 엔지니어, 컴퓨테이셔널 포토그래피 연구원, 광학 시뮬레이션 전문가, Core ML·Metal 최적화 엔지니어다.

개발 대상:

- GitHub: https://github.com/MetaParodica/PhotoP
- 플랫폼: iPhone / iOS 18 이상
- 기술: SwiftUI, AVFoundation, Vision, Core ML, Core Image, Metal
- 언어 설정: Swift 5, Strict Concurrency Complete

PhotoP를 Leica LUX와 경쟁할 수 있는 전문 카메라로 고도화한다.

최우선 목표는 DSLR·미러리스 카메라와 시각적으로 비교할 수 있는 소프트웨어 심도 품질이다.

단순한 배경 Gaussian Blur나 Apple 인물 모드 래퍼를 개발하는 것이 아니다. 실제 광학 렌즈의 흐림, 보케, 초점 전환, 전경·후경 가림, 피사체 경계를 물리 기반 렌더링과 신경망 보정으로 구현해야 한다.

Leica LUX, Focos, ReLens 및 실제 DSLR·미러리스 결과를 품질 비교 대상으로 삼는다.

실측 전에 경쟁 제품보다 우수하거나 동일한 성능이라고 선언하지 않는다.

## 2. 광학 기반 심도 엔진 고도화 — 최우선 P0

현재 PhotoP는 signed CoC, 깊이 레이어, 디스크 PSF 근사, 전경·후경 합성, 초점면 보호와 렌즈 프로필을 지원한다.

이를 처음부터 교체하지 말고 기존 처리 파이프라인을 확장한다.

### 2.1 Physically Based PSF Renderer

구현 목표:

- Circle of Confusion의 물리 기반 계산
- 전경과 후경에 대한 서로 다른 렌더링
- 화면 위치별 공간 가변 PSF
- 조리개 블레이드 형상
- Cat-eye Bokeh
- 주변부 보케 변형
- 광량 보존
- 하이라이트 보케의 정확한 합성
- 포커스 앞뒤의 색수차 효과
- 필요시 비네팅·구면수차의 선택적 재현

실측 정보가 없는 광학 효과는 정확한 렌즈 복제 기능이 아닌 스타일 프로필로 구분한다.

현재 `DepthLensFilter`와 관련 참조 렌더러를 조사하여 필요한 부분만 수정한다.

CPU 참조 구현과 Metal 처리 결과를 비교 검증한다.

### 2.2 올바른 빛의 합성

색·알파·깊이 처리 순서를 점검한다.

특히 다음 오류를 줄인다.

- 흐려진 배경이 인물 외곽을 침범
- 피사체 경계에 밝은 후광 발생
- 밝은 보케가 어둡게 뭉개짐
- 전경 흐림이 잘못된 위치에 나타남
- 초점면이 지나치게 날카롭게 잘림
- 어두운 영역에서 색상 번짐
- 배경 색상이 인물 머리카락에 섞임

필요시 선형 광량 공간에서 보케를 처리하고, 기존 SDR 색 관리 계약과 일관성을 검증한다.

단순히 Blur Radius를 증가시키는 작업을 품질 개선으로 간주하지 않는다.

### 2.3 Multi-Layer Occlusion

현재 Depth Layer 처리 방식을 기반으로 가림 관계를 개선한다.

- foreground / focal plane / background 구분
- 깊이 순서에 따른 알파 합성
- 전경 보케의 자연스러운 확산
- 피사체 뒤쪽 배경의 제한적 확장
- 가려진 배경 색상의 오염 방지
- 경계별 불확실성 처리

보이지 않았던 배경을 정확하게 복원했다고 주장하지 않는다.

참고 연구:

- Dr. Bokeh — CVPR 2024
- BokehMe / BokehMe++
- Bokehlicious — ICCV 2025

논문·공식 저장소·실제 구현을 조사하고, 검증 가능한 알고리즘부터 적용한다.

## 3. 고정밀 피사체 매팅 — P0

현재 선택 피사체 매트·RGB 기반 알파 및 경계색 보정 구현을 재사용한다.

개선 대상:

- 머리카락 한 올 수준의 얇은 구조
- 역광 머리카락
- 안경테와 렌즈
- 손가락 사이 공간
- 나뭇잎과 잔가지
- 반투명 의류
- 동물 털
- 다중 인물의 겹침
- 유리와 반사면의 불확실 영역

기존 Portrait Matte, Semantic Matte, AI 마스크의 처리 구조를 확인한다.

외부 모델 후보:

- MatAnyone
- Robust Video Matting
- SAM 계열
- EfficientTAM

위 후보를 모두 추가하지 않는다.

기존 모델 대비 실제 경계 품질이 개선되는 후보를 선별하고, 작은 Core ML 모델로 전환 가능한지 평가한다.

추론이 무거우면 빠른 촬영 프리뷰와 고품질 최종 사진 처리 경로를 분리한다.

고정밀 매팅을 전체 영상 프레임에 강제로 실행하지 않는다.

## 4. Temporal Depth Consistency — P0

현재 영상 심도 파이프라인은 각 프레임의 깊이를 새로 추정한다.

이 방식의 시간적 깜빡임과 척도 변동을 개선하는 것이 핵심 과제다.

다음 기술을 조사·구현한다.

### 4.1 Video Depth Anything Small

- 스트리밍 깊이 추정 구조 분석
- Core ML 변환 가능성 조사
- 시간적 깊이 일관성
- 프레임별 상대 깊이 scale/shift 정렬
- 카메라 이동 시 깊이 안정화
- 장면 전환 감지
- 빠른 움직임과 모션 블러 대응

메모리·성능 기준을 만족하지 못하면 기존 Depth Anything V2 기반 경로를 유지한다.

### 4.2 Optical Flow 기반 Temporal Stabilization

기존 Vision Optical Flow 구현과 통합한다.

- 이전 깊이의 현재 좌표 워프
- 가림·새로 등장한 영역 감지
- 프레임 불일치 시 이전 깊이 폐기
- 불확실 깊이의 시간적 가중치 제어
- 영상 컷에서 상태 초기화
- 만료된 결과의 재사용 금지

단순 프레임 평균이나 무조건적인 시간 필터링은 금지한다.

### 4.3 영상 화질 테스트

최소한 다음 상황을 구분해 테스트한다.

- 정지 인물
- 천천히 걷는 인물
- 빠르게 움직이는 인물
- 카메라 팬
- 카메라 전후 이동
- 전경의 갑작스러운 등장
- 인물 가림 및 재등장
- 복수 피사체 교차
- 역광 머리카락
- 야간 점광원

시간적 깜빡임, 초점 대상 이탈, 경계 흔들림, 원본 fallback 비율을 수집한다.

## 5. 고정밀 피사체 추적 — P1

기존 Vision 추적·ByteTrack 점수 융합 참고 구현을 재사용한다.

현재 Bounding Box 추적은 픽셀 단위 마스크 추적이나 장기 객체 식별이 아니므로 이 부분을 고도화한다.

목표:

- 선택한 대상에 대한 세밀한 마스크 추적
- 부분 가림 이후 재추적
- 여러 대상의 마스크 분리
- 대상 교차 시 오인식 최소화
- 터치로 추적 대상 변경
- 초점 대상과 마스크의 일치
- 낮은 confidence에서 안전한 원본 복귀

EfficientTAM을 우선 PoC 후보로 조사한다.

다만 실제 모델 크기, Neural Engine 지원, 메모리 사용량, 프레임 처리량, 상용 배포 조건과 모델 출처를 검증한 뒤 적용한다.

얼굴 검출을 생체 신원 인식으로 표현하지 않는다.

## 6. 렌즈별 광학 시뮬레이션 — P1

현재 Natural / Portrait / Classic 프로필을 보존한다.

광학 렌즈별 추가 프로필을 개발한다.

초기 연구 대상:

- 28mm 광각
- 35mm 스냅
- 50mm 표준
- 75mm 인물
- 85mm 인물
- 90mm 망원 인물

단, 사용자가 선택한 렌즈 프로필이 실제 물리 초점거리를 바꾸거나 iPhone이 지원하지 않는 광학 줌을 제공한다고 표시하지 않는다.

프로필은 다음 파라미터를 활용한다.

- PSF
- CoC 특성
- 하이라이트 형태
- 주변부 변형
- 수차
- 비네팅
- 색상 특성
- 명암 전환

Leica Summilux·Summicron 및 주요 DSLR·미러리스 렌즈를 비교 연구 대상으로 사용할 수 있다.

브랜드와 특정 제품을 정확하게 재현한다고 표시하기 전에는 실측과 권리 검토가 필요하다.

실측 없는 프로필은 독자적인 스타일 이름을 사용한다.

## 7. 사진·영상 편집 고도화 — P1

기존 촬영 후 재초점, f값 변경, 원본 비교와 보관함 기능을 보존한다.

다음 기능을 추가 검토한다.

### 7.1 Depth Correction Brush

사용자가 잘못된 깊이 영역을 직접 보정한다.

- 영역을 선택하여 전경으로 지정
- 영역을 선택하여 배경으로 지정
- 마스크 경계 부드러움 조절
- 선택한 깊이 범위 보호
- Undo / Redo
- 원본 Depth Map 비파괴 보존
- 수정 결과를 별도 레시피에 저장

전체 이미지의 깊이를 임의 숫자로 덮어쓰지 말고, 기존 깊이 지도와 수정 마스크의 충돌을 처리한다.

### 7.2 사진 초점 제어

- 터치한 위치의 초점면 미리보기
- 선택 피사체 강조 표시
- Depth Map 보기
- Alpha Matte 보기
- 불확실 영역 표시
- 초점면 범위 가이드
- 원본/결과 비교

### 7.3 영상 초점 제어

기존 시간별 심도 설정을 확장한다.

- 초점 위치 키프레임
- f값 키프레임
- 부드러운 전환 곡선
- 전환 미리보기
- 키프레임 간 보간
- 추적 실패 시 이전 대상에 잘못 고정되지 않는 정책

사진·영상의 기존 레시피 호환성을 유지한다.

## 8. 고품질 출력과 성능 최적화 — P0/P1

기존 고해상도 타일 렌더링과 GPU 자원 수명 관리 정책을 유지한다.

촬영 프리뷰는 빠른 경로, 최종 저장은 고화질 경로로 구분한다.

검토 항목:

- Metal PSF 커널 최적화
- Depth Map과 Matte 재사용
- 불필요한 Core ML 추론 방지
- GPU 타일 처리
- 제한된 중간 버퍼
- 프레임별 메모리 재사용
- 작업 취소
- generation과 snapshot revision 검증
- 열 상태별 처리 예산
- 오래된 작업 자동 폐기
- Core ML 추론 우선순위 스케줄러

사진은 기존 최대 64MP 처리 계약을 훼손하지 않는다.

영상은 현재 8비트 SDR 파생 출력을 유지하면서 10비트 SDR 출력의 기술적 가능성을 별도로 검토한다.

HDR, Gain Map, Log 영상, C2PA는 현재 사용자 결정에 따라 도입하지 않는다.

원본 RAW·ProRAW·사진·MOV 파일의 bytes와 SHA-256은 변경하지 않는다.

## 9. 기존 촬영 UX 개선 — P1/P2

기존 촬영 UI에서 실제 미구현 또는 조작이 불편한 기능만 추가한다.

후보:

- C1/C2/C3 사용자 촬영 프리셋
- 사용자 구성 가능한 빠른 설정
- 독립 수평계
- 선택 초점 위치 확대
- 가상 조리개와 실제 노출의 구분
- 심도 프리뷰 신뢰도 표시
- 사진과 영상 간 공통 렌즈 설정
- 초점/렌즈/마스크 편집 상태의 명확한 표시
- 저장 공간 예측 및 실패 복구
- 보관함 파생 결과 검색 및 관리

AI 구도 추천·코치·자동 리뷰는 기존 사용자 결정에 따라 중지 상태를 유지한다.

기존 기능을 중복해서 만들지 않는다.

## 10. 연구·오픈소스 활용 정책

공식 문서, 논문, 소스 저장소, Apple API를 직접 조사한다.

우선 연구 대상:

- Dr. Bokeh
- Bokehlicious
- BokehMe / BokehMe++
- Depth Anything V2
- Video Depth Anything
- EfficientTAM
- MatAnyone
- Robust Video Matting
- Apple Vision / AVFoundation / Core ML / Metal

기존 프로젝트에 재사용 가능한 기술이 있다면 새로 작성하기 전에 검토한다.

필요한 코드를 이식할 수 있으나 다음 정보를 반드시 기록한다.

- 프로젝트 URL
- 원본 commit SHA
- 실제 복사·수정 범위
- 라이선스 및 NOTICE
- 모델 가중치와 데이터셋의 별도 조건
- 파일 hash
- 실제 앱 포함 여부

조사했다고 구현 완료로 표기하지 않는다.

모델을 가져왔다고 Core ML 변환 성공이나 iPhone 실시간 구동 성공으로 주장하지 않는다.

## 11. 개발 순서

다음 순서로 진행한다.

### Phase 0 — 현행 코드 정밀 감사

현재 구현과 테스트를 파악하고 기능 중복을 제거한다.

완료 기준:

- 기능별 구현 상태표
- 구체적 파일·함수 목록
- 실제 실패 지점
- 변경이 필요한 최소 모듈 목록
- 검증 가능한 개발 계획

### Phase 1 — 심도 품질 기준선

현재 NaturalDepthEngine의 결과를 fixture와 평가 사진으로 측정한다.

검증:

- 기존 테스트 모두 통과
- 화질 평가용 데이터 형식 확정
- 실제 샘플이 없는 항목은 미검증으로 표시

### Phase 2 — PSF·Occlusion 렌더링 고도화

현재 광학 렌더러를 확장한다.

검증:

- CPU 참조 구현
- Metal 출력 비교
- CoC 연속성
- 점광원 에너지
- 경계 halo
- 전경/후경 가림
- 원본 hash 불변

### Phase 3 — 고정밀 매팅

기존 매트 경로에 필요한 개선만 추가한다.

검증:

- 경계 알파
- 가는 구조
- 전경 spill
- 저신뢰 fallback
- 기존 사진 재편집 호환성

### Phase 4 — 영상 깊이 안정화

Video Depth Anything 등의 기술을 PoC로 비교한 후, 실제 개선이 확인되는 방식을 통합한다.

검증:

- 시계열 깊이 정합
- 장면 컷
- 가림
- 빠른 이동
- 추적 실패 복귀
- 원본 PTS/오디오/방향 보존

### Phase 5 — 렌즈 프로필 및 UX

광학 프로필과 Depth Correction Brush를 구현한다.

검증:

- 프로필별 실제 렌더링 변화
- 편집 레시피 호환성
- 저장·취소·재시작
- 고해상도 출력

### Phase 6 — 최종 성능·품질 평가

현재 저장소에 있는 심도 acceptance gate와 연동한다.

실제 평가 사진 최소 100장과 영상 테스트 장면을 사용한다.

Leica LUX, iPhone 기본 카메라, DSLR·미러리스 참고 사진과 블라인드 비교한다.

실제 사용자의 평가 자료가 없다면 임의로 통과 결과를 만들지 않는다.

## 12. 절대 지켜야 할 프로젝트 정책

1. 기존 코드에서 동작하는 기능을 불필요하게 재작성하지 않는다.
2. 관련 없는 코드와 UI를 변경하지 않는다.
3. API 지원 여부를 확인하지 않은 기능을 활성화하지 않는다.
4. 원본 바이트를 절대 수정하지 않는다.
5. 파생 파일은 UUID 번들로 원자적으로 게시한다.
6. 기존 사진·영상·RAW·LUT·AF/MF 기능을 유지한다.
7. 설정 변경 중 오래된 비동기 결과가 적용되지 않도록 한다.
8. 기존 테스트를 삭제하거나 무력화해 성공 처리하지 않는다.
9. Simulator 성공과 실기기 화질 성공을 구분한다.
10. 실제 검증하지 않은 성능·화질·모델 도입을 완료로 표시하지 않는다.
11. iOS 18 최소 지원과 기존 SDK 조건을 유지한다.
12. 새로운 기능이 기존 레시피와 보관함을 깨지 않도록 마이그레이션 또는 호환 복원 정책을 적용한다.
13. 위치 태깅, 공유본의 위치 제거, AI 결과 표시와 기타 미완료 사용자 정책을 임의로 변경하지 않는다.
14. 재검증 전에 main에 위험한 변경을 직접 덮어쓰지 않는다.

## 13. 테스트와 게시

각 Phase마다:

1. 변경 전 기준 테스트
2. 최소 구현
3. 관련 단위 테스트
4. 이미지·영상 fixture 테스트
5. Xcode 네이티브 빌드
6. Simulator UI 테스트
7. 전체 CI
8. 실패 분석 및 수정
9. 기존 기능 회귀 확인

순서로 반복한다.

최신 `CLAUDE.md`와 `.github/workflows/ios.yml`을 따라 실행한다.

실제 기기 검증이 불가능하면 GitHub Actions 성공을 실기기 검증으로 대체하지 않는다.

각 단계의 문서와 검증 결과를 갱신한다.

- `docs/08-STEP-VALIDATION.ko.md`
- `docs/32-NEXT-TASK-BACKLOG.ko.md`
- 신규 심도 고도화 구현 문서
- `docs/development-log/YYYY-MM-DD.md`
- 개발 일지 색인

기존 일지 내용은 삭제하지 않는다.

브랜치 작업 후 성공한 소스를 기존 프로젝트 규칙에 따라 게시한다. main 반영은 기존 승인 범위·사용자 지시·저장소 협업 규칙에 부합하는 경우에만 수행한다. 강제 push하지 않는다.

## 14. 최종 보고서 형식

다음 항목을 빠짐없이 보고한다.

1. 확인한 실제 main SHA
2. 기존 구현되어 있었던 기능
3. 새로 구현한 기능
4. 수정한 파일과 함수
5. 외부에서 재사용한 기술과 출처
6. 기존 대비 변경된 심도 알고리즘
7. 실제 품질 개선을 입증하는 테스트 결과
8. 성능·메모리·발열 측정 결과 또는 미측정 사유
9. 테스트 수, skip, 실패 및 해결 내용
10. CI 실행 URL과 정확한 검증 SHA
11. 실기기 미검증 항목
12. 남은 기능과 다음 개발 우선순위
13. 커밋·브랜치·푸시 상태

최종 성공 기준은 단순히 코드가 컴파일되는 것이 아니다.

**PhotoP가 현재보다 자연스러운 인물 경계, 전경·후경 보케, 시간적으로 안정적인 영상 심도, 비파괴 전문 편집 기능을 실제 측정과 재현 가능한 테스트로 입증하는 것이다.**

기존 엔진을 최대한 활용하여 불필요한 재구현을 피하고, 실제 화질에 영향을 주는 핵심 알고리즘에 개발 역량을 집중하라.
